apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: springboot-ingress
  namespace: default
spec:
  ingressClassName: nginx  # Updated to use spec field instead of annotation
  rules:
  - host: "springboot.local"
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: springboot-api-service
            port:
              number: 80


OR 
- annotation based 

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: springboot-ingress
  namespace: default
  annotations:
    kubernetes.io/ingress.class: "nginx"  # Tells Kubernetes to use the NGINX Ingress Controller
spec:
  rules:
  - host: "springboot.local"  # A fake domain for testing with Minikube
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: springboot-api-service
            port:
              number: 80

Ingress Commands Cheat Sheet

    kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/main/deploy/static/provider/cloud/deploy.yaml
        Why: Sets up the NGINX Ingress Controller to handle traffic routing.
        What: Deploys NGINX resources (pods, services, etc.) in ingress-nginx namespace.
        Output:

        namespace/ingress-nginx created
        deployment.apps/ingress-nginx-controller created
        ...

            Lists created resources; no errors = success.
    kubectl apply -f springboot-ingress.yaml
        Why: Defines how traffic routes to our Spring Boot API.
        What: Creates/updates the springboot-ingress resource with our rules.
        Output:

        ingress.networking.k8s.io/springboot-ingress created

            "created" or "configured"; might warn about deprecated annotations if old format.
    kubectl get ingress -n default
        Why: Checks if our Ingress is active and has an IP.
        What: Lists Ingress resources in default namespace.
        Output:

        NAME                 CLASS    HOSTS              ADDRESS        PORTS   AGE
        springboot-ingress   <none>   springboot.local   192.168.49.2   80      5m

            ADDRESS filled means it’s working; blank means trouble.
    kubectl get pods -n ingress-nginx
        Why: Ensures the Ingress Controller is running.
        What: Shows pods in ingress-nginx namespace.
        Output:

        NAME                                       READY   STATUS    RESTARTS   AGE
        ingress-nginx-controller-d8c96cf68-spr5n   1/1     Running   0          10m

            1/1 Running = good; anything else needs fixing.
    kubectl logs -n ingress-nginx -l app.kubernetes.io/name=ingress-nginx
        Why: Debugs Ingress Controller issues.
        What: Dumps NGINX pod logs.
        Output:

        [15/Mar/2025:12:00:00] "GET /helloworld HTTP/1.1" 200 ...

            Request logs or errors (e.g., "port unavailable").
    kubectl get service -n ingress-nginx
        Why: Verifies the Ingress Controller’s external ports.
        What: Lists services in ingress-nginx.
        Output:

        NAME                        TYPE       CLUSTER-IP      EXTERNAL-IP   PORT(S)                      AGE
        ingress-nginx-controller    NodePort   10.96.x.x       <none>        80:31234/TCP,443:32456/TCP   15m

            NodePort (e.g., 31234) is our external access point.
    kubectl describe ingress springboot-ingress -n default
        Why: Troubleshoots Ingress setup details.
        What: Shows spec, events, and status.
        Output:

        Name:             springboot-ingress
        Address:          192.168.49.2
        Rules:            springboot.local  /  springboot-api-service:80
        Events:           <success messages>

            Errors in Events highlight issues.
    minikube addons enable ingress
        Why: Activates Minikube’s NGINX Ingress for easy setup.
        What: Deploys a Minikube-tuned Ingress Controller.
        Output:

        * The 'ingress' addon is enabled

            Confirms it’s on; pods start in ingress-nginx.
    minikube addons list | grep ingress
        Why: Checks Ingress addon status.
        What: Filters addon list.
        Output:

        | ingress              | enabled    | ingress               |

            enabled = active; disabled = off.
    curl http://springboot.local/helloworld
        Why: Tests if Ingress routes to our API.
        What: Sends a request via our hostname.
        Output:

        Hello World

            our API’s response; failure (e.g., Could not connect) means a problem.
    curl http://192.168.49.2
        Why: Tests Ingress Controller directly, skipping hostname.
        What: Hits Minikube IP.
        Output:

        Hello World

            Or 404; works here but not with hostname = routing/hosts issue.

Quick Notes

    These commands span setup (apply), monitoring (get, describe), and testing (curl).
